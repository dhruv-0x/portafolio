Qué cambia en esta versión

La mejora no es solo estética. La estructura cambia para que el portafolio sea más fácil de mantener, más escalable y mucho más convincente para mostrar tus capacidades y vender tus servicios.

Antes

El bloque de agregar proyectos dependía de localStorage. Eso sirve para pruebas, pero en GitHub Pages no te permite publicar cambios permanentes para todos los visitantes. Además, mezclar contenido y lógica dentro del mismo HTML vuelve el mantenimiento más incómodo.

Ahora

Los proyectos se leen desde data/projects.json. Tú puedes agregar uno nuevo copiando una estructura sencilla o usar el panel para importar/exportar. Así separas contenido, presentación y comportamiento, que es una forma mucho más limpia de trabajar.

Cómo trabajo

La idea es mostrar que no solo programas, sino que entiendes cómo convertir una necesidad en un proyecto útil y bien presentado.

Paso 01

Analizo el problema

Defino qué quiere comunicar el proyecto, qué objetivo tiene y cuál es la mejor forma de convertirlo en una solución clara y atractiva.

Paso 02

Diseño la estructura

Ordeno secciones, jerarquía visual, experiencia del usuario y la lógica interna para que todo tenga coherencia desde el inicio.

Paso 03

Construyo y optimizo

Desarrollo, pruebo, ajusto animaciones, reviso responsive y dejo el resultado listo para mostrar y también para vender.

Agregar o editar proyectos

Aquí está la parte importante: ahora tienes una forma limpia de gestionarlos desde GitHub o desde el navegador sin dañar la estructura del portafolio.

Opción recomendada para GitHub Pages

Edita data/projects.json en tu repositorio. Cada objeto es un proyecto nuevo. Guardas, haces commit y GitHub Pages publica los cambios.
